# 세션 이어가기 프롬프트 만들기

다음 세션의 Claude는 이 대화를 볼 수 없다. 레포와 이 프롬프트만으로 바로 일을 시작할 수 있게 만든다.

## 1. 사실 모으기 (추측하지 말고 확인)

다음을 직접 확인한다.

- `git status`, `git branch --show-current`, `git log --oneline -15`: 지금 브랜치, 최근 커밋, 커밋 안 된 변경
- `docs/ROADMAP.md`: 끝난 것과 남은 것
- `CLAUDE.md`, `docs/GAME_DESIGN.md`, `docs/ART_PROMPTS.md`: 확정된 규칙과 이번에 바뀐 결정
- 배포 주소, 연결된 다른 레포(예: `songok14/FishingPlan`은 읽기 전용)
- 이 대화에서 사용자가 새로 정한 것: 방향 전환, 취향, 말투와 형식 요구, 거절한 것

커밋 안 된 변경이 있으면 먼저 커밋하고 푸시한다. 레포에 없고 이 세션 작업 폴더에만 있는 것(원본 그림 등)은 따로 적어서 사용자에게 알린다.

## 2. 프롬프트 쓰기

한국어로, **코드 블록 하나**에 담는다. 사용자가 통째로 복사해서 붙여 넣는다. 섹션은 이 순서로 쓴다.

```
<레포>의 <게임 이름> 작업을 이어서 해 줘. 모든 답변, 문서, 커밋 메시지, 코드 주석은 한국어로 써줘.

## 지금까지 상황
- 브랜치, 배포 주소, 지금 버전이 어디까지 됐는지
- 먼저 읽을 파일 목록
- 다른 레포나 외부 자료와의 관계 (읽기 전용 여부)

## 확정된 결정
- 기술, 그림체, 글꼴, 비용 원칙 등 바꾸면 안 되는 것
- 이번 세션에서 바뀐 결정은 "바뀐 점"으로 따로 표시

## 사용자 선호
- 답변 형식 (예: 그림 프롬프트는 한 장당 코드 블록 하나, 복붙용)
- 작업 방식 (예: 스크린샷을 먼저 보여 주기, PR은 요청할 때만)

## 이번 세션에서 해 줬으면 하는 것
1. 구체적인 첫 작업부터 순서대로, 끝나는 기준과 함께
2. ...
마지막: 확인 방법(빌드, 테스트, 스크린샷)과 커밋·푸시
```

쓰는 원칙:
- 사실만 쓴다. 확인 못 한 것은 "확인 필요"라고 적는다.
- 다음 세션이 다시 물어볼 필요가 없게 결정 내용을 구체적으로 적는다(예: "귀여운 그림" 대신 "배경과 어울리는 2~2.5등신 SD 캐릭터, 일러스트는 컷신에만").
- 환경 제약을 적는다(예: 클라우드에서는 유니티 에디터를 못 돌린다 → 순수 C# 코어는 여기서 테스트, 에디터 작업은 사용자 PC).
- 파일 경로는 레포 기준 상대 경로로 쓴다.

## 3. 저장하고 알리기

1. 같은 내용을 `docs/HANDOFF.md`에 저장한다. 맨 위에 작성 날짜와 브랜치를 적고, 프롬프트는 코드 블록으로 넣는다. 예전 내용은 덮어쓴다(지난 기록은 git에 남는다).
2. 커밋하고 푸시한다.
3. 사용자에게 프롬프트 코드 블록을 그대로 보여 주고, 레포에 없어서 세션이 끝나면 사라지는 것이 있으면 한 줄로 알린다.
