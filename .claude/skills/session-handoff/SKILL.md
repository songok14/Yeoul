# 이어가기 프롬프트 만들기

다음 대화의 Claude는 지금 대화를 볼 수 없다. 이 프롬프트(와 레포가 있다면 레포)만으로 다시 묻지 않고 바로 일을 시작할 수 있게 만든다. 답변은 사용자가 쓰는 언어로 쓴다.

## 1. 사실 모으기 (추측하지 말고 확인)

**코드 레포에서 작업 중이면** 직접 확인한다.
- `git status`, `git branch --show-current`, `git log --oneline -15`: 브랜치, 최근 커밋, 커밋 안 된 변경
- `CLAUDE.md`, `README.md`, `docs/` 안의 계획·로드맵·설계 문서가 있으면 읽고, 끝난 것과 남은 것을 나눈다
- 배포 주소, 연결된 다른 레포와 권한(읽기 전용 등), CI 상태
- 커밋 안 된 변경이 있으면 사용자에게 알리고, 사용자가 원하면 커밋·푸시한다

**레포가 없는 일반 대화면** 대화 내용에서 모은다.
- 목표, 지금까지 만든 결과물, 정한 결정, 남은 일
- 참고한 자료와 파일 이름 (다음 대화에서 다시 첨부해야 할 것)

두 경우 모두 이 대화에서 사용자가 새로 정한 것을 빠뜨리지 않는다: 방향 전환, 취향, 답변 형식 요구, 거절하거나 접은 선택지와 그 이유.

## 2. 프롬프트 쓰기

**코드 블록 하나**에 담는다. 사용자가 통째로 복사해서 붙여 넣는다. 섹션은 이 순서로, 해당 없는 섹션은 뺀다.

```
<무엇을> 이어서 해 줘. (언어 요구가 있으면 여기에: 예 "모든 답변과 문서는 한국어로")

## 지금까지 상황
- 어디까지 됐는지 (레포·브랜치·배포 주소·결과물)
- 먼저 읽거나 다시 첨부할 것

## 확정된 결정
- 바꾸면 안 되는 것 (기술, 스타일, 비용 원칙 등)
- 이번에 바뀐 결정은 "바뀐 점"으로 따로, 접은 선택지는 이유와 함께

## 사용자 선호
- 답변 형식, 작업 방식 (예: 복붙용 코드 블록, 결과물 먼저 보여 주기, PR은 요청할 때만)

## 환경 제약
- 다음 대화에서 못 하는 것과 대신 쓰는 방법

## 이번에 해 줬으면 하는 것
1. 첫 작업부터 순서대로, 끝나는 기준과 함께
2. ...
마지막: 확인 방법(빌드, 테스트, 결과 확인)과 저장·커밋 방법
```

쓰는 원칙:
- 사실만 쓴다. 확인 못 한 것은 "확인 필요"라고 적는다.
- 다음 대화가 다시 물어볼 필요가 없게 결정을 구체적으로 적는다 ("예쁘게" 대신 "2~2.5등신 SD, 배경은 수채화").
- 파일 경로는 레포 기준 상대 경로로 쓴다.
- 길이보다 빠짐없음이 중요하지만, 대화 기록을 옮겨 적지는 않는다.

## 3. 저장하고 알리기

1. 레포가 있으면 같은 내용을 `docs/HANDOFF.md`에 저장한다(맨 위에 날짜와 브랜치, 프롬프트는 코드 블록). 예전 내용은 덮어쓴다. 사용자가 원하면 커밋·푸시한다.
2. 사용자에게 프롬프트 코드 블록을 그대로 보여 준다.
3. 대화가 끝나면 사라지는 것(임시 폴더의 파일, 첨부했던 원본 등)이 있으면 한 줄로 알린다.
4. 같은 작업을 이미 다른 세션이 하고 있으면, 두 세션이 같은 브랜치·파일을 동시에 고치지 않게 알린다.
